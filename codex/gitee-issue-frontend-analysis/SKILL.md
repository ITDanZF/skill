# Gitee 单问题前端分析

以用户提供的一条 Gitee issue/bug 链接为问题来源，结合当前工作区前端代码完成只读诊断，并输出可供产品、前端、后端和测试共同评审的报告。

## 边界

- 默认只读取 Gitee 和本地仓库，不编辑代码，不更新、评论或流转 Gitee 问题。用户另外明确要求修改时，结束报告后再按对应开发流程处理。
- 只分析用户给出的单条问题及其直接相关代码。关联问题仅作为证据，不扩展成批量审计。
- 不把推测写成事实，不按人员归责；责任判定面向系统边界或交付环节。
- 不输出登录凭据、Cookie、Token 或与问题无关的内部信息。

## 取证

1. 打开用户提供的 Gitee 链接。优先使用可引用的网页读取能力；企业 Gitee 需要登录态或页面交互时，读取并使用可用的 `computer-use` 技能访问当前浏览器会话。
2. 提取与判断有关的信息：标题、问题编号、状态、优先级、环境、前置条件、复现步骤、实际结果、预期结果、附件、评论中的澄清、关联提交以及最近更新时间。
3. 如果链接无法访问、权限不足或关键附件不可读，说明缺少的证据及其对结论的影响。可以继续做有限代码分析，但责任结论必须标为“暂无法判定”；不要根据标题猜测详情。
4. 检查当前仓库适用的 `AGENTS.md` 和工作区状态。使用 `rg` 从页面路由、可见文案、接口地址、字段名、组件名和报错信息切入，追踪：
   - 路由或入口组件；
   - API 请求与响应适配；
   - store/composable 的状态和数据流；
   - 页面渲染、权限、校验和交互；
   - 相关测试、配置和接口文档。
5. 需要复现时只执行安全、只读或临时性的检查。记录观察结果，不为生成报告而改代码。

## 责任判定

在以下边界中选择主责和可能的协同责任：前端、后端/API、数据或配置、产品/需求、设计交互、部署/环境、第三方依赖、共同责任、暂无法判定。

- 责任必须由“问题要求/接口契约/代码实际行为/运行证据”之间的差异支持。
- 区分根因、触发条件和放大因素。前端表现出错误不等于前端主责，后端字段异常也不自动等于后端主责。
- 给出置信度：高、中、低，并列出能改变判定的缺失证据。
- 需求或接口契约相互矛盾时，优先判为产品/接口协同问题，不武断指定单方。

## 修改建议与范围

- 给出最小闭环方案，并按“必须修改 / 建议优化 / 无需修改”区分。
- 每项建议写明所属端、目标行为、关键文件或接口、验证方式；不在报告中伪造补丁。
- 修改范围列出直接文件、受影响调用链、接口字段、状态、权限、配置、测试和文档。无法确认的文件使用候选范围并说明原因。
- 风险至少覆盖回归、兼容、数据、接口时序、权限/安全、性能和发布回滚；不相关项写“未发现明显风险”，不机械凑项。

## 输出

生成报告前读取 [references/report-template.md](references/report-template.md)，按其中结构输出。默认使用中文，并将 Gitee 链接和本地代码证据链接放在对应结论附近。
