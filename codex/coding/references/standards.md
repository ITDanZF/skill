# 编码规范

用这个文件沉淀跨项目适用的个人编码规则。

## 默认规则

- 优先遵循项目已有模式，而不是创建新抽象。
- 修改保持小而直接，围绕明确行为展开。
- 简单、低风险修改可以走轻量对话确认，不必生成正式 Markdown 分析文档。
- 用户明确跳过完整流程时，可以跳过；但高风险、破坏性或边界不清的任务仍需先问清楚。
- 生成分析 Markdown 后，必须在对话框中给出文件路径；VS Code 自动打开只是尽力尝试，不能作为唯一预览方式。
- 需要用户确认时，必须在对话框中提出一个明确问题，并提供 2-4 个可选项；不能只写在 Markdown 文档中。
- 只有在能解释非显然逻辑时才添加注释。
- 除非任务要求格式化，否则避免大范围格式化噪音。
- 保留用户已有修改，不回滚无关工作。

## 验证

- 优先运行能可靠验证本次修改的最快检查。
- 不要每次默认运行完整构建、完整编译或全量测试。
- 如果无法运行检查，说明原因，并点明未验证风险。
- 如果跳过完整构建，说明已执行的快速验证和剩余风险。

## 代码审查标准

- 优先关注正确性、回归风险、边界情况、安全、性能和缺失测试。
- 做 review 时先列问题；能定位时提供文件和行号。
